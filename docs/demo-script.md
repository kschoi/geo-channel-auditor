# 고객 인식 분석 · 실제 앱 5분 시연

실제 앱 화면과 공개 검색 자료로 구성한다. 대상은 **산본 디델리 분식**, 경쟁점은 **산본 두끼 분식**, 기간은 **최근 1년**이다. API 응답 대기는 편집 표시를 넣는다.

영상은 300초다. 화면 수치는 실제 결과를 그대로 보여주며, 대본에서 결과 수치를 미리 단정하지 않는다.

## 00:00:00–00:00:32 · 우리 매장을 보는 손님의 시선

화면: 첫 화면 전체, 매장 검색어 입력

고객은 우리 매장을 어떻게 볼까요? 매장 인사이트에서 실제 공개 자료를 찾아보겠습니다.

매장 사장님이 후기를 하나씩 읽다 보면, 무엇이 좋았고 무엇이 아쉬웠는지 놓치기 쉽습니다.

이 앱은 검색으로 찾은 후기와 웹문서를 모아, 어떤 경험이 언급됐는지 정리합니다.

먼저 산본 디델리 분식을 입력합니다. 동네와 매장명을 함께 적어 같은 이름의 다른 지점과 구분합니다.

여기서 살펴보는 대상은 이번에 찾은 문서입니다. 전체 고객의 만족도를 측정하는 것은 아닙니다.

## 00:00:32–00:01:10 · 경쟁점과 기간을 정하고 검색

화면: 경쟁점·분석 기간 설정 펼침, 실제 실행, 진행 메시지

경쟁점과 분석 기간 설정을 펼치면, 비교할 매장을 최대 두 곳까지 직접 넣을 수 있습니다.

이번에는 산본 두끼 분식을 경쟁점으로 넣고, 게시일은 최근 일 년을 선택합니다.

육 개월이나 삼 개월로 바꿀 수도 있습니다. 모든 매장은 같은 기간과 검색 횟수로 자료를 모읍니다.

고객 인식 살펴보기를 누르면 실제 검색이 시작됩니다. 진행 메시지로 현재 단계를 확인할 수 있습니다.

영상에서는 에이피아이 응답을 기다리는 구간을 줄였습니다. 검색 뒤에는 매장, 게시일, 중복 자료를 확인합니다.

에이아이가 작성한 설명 자체가 아니라, 연결된 공개 자료의 문장을 근거로 사용합니다.

## 00:01:10–00:01:50 · 요약 숫자가 뜻하는 범위

화면: 리포트 제목과 날짜, 인식 요약, 날짜 미확인·홍보 문서 안내

분석 결과의 첫 화면입니다. 매장 이름과 분석 기간을 먼저 확인합니다.

요약에는 기간 안에 게시된 고객 경험 문서를 긍정, 부정, 혼합, 중립으로 나눠 보여줍니다.

한 문서 안에 좋은 경험과 아쉬운 경험이 함께 있으면 혼합으로 표시합니다.

문서 한 건을 고객 한 명으로 세지 않습니다. 같은 문서를 여러 번 찾았다고 숫자를 늘리지도 않습니다.

아래에는 날짜를 확인하지 못한 고객 경험과 홍보, 기사 같은 자료가 따로 표시됩니다.

날짜가 없으면 선택한 기간에 속하는지 알 수 없어서, 주요 비율에는 넣지 않습니다.

따라서 숫자가 적거나 비어 있다면, 만족도가 낮다는 뜻이 아니라 지금 확보한 근거가 부족하다는 뜻입니다.

## 00:01:50–00:02:35 · 경험별 비교와 비교 한계

화면: 항목×매장 행렬, 제한 안내, 숫자로 비교하기 펼침

다음은 어떤 경험에서 차이가 나는지 보는 화면입니다. 품질, 서비스, 가격과 가치 같은 항목으로 나뉩니다.

각 사각형은 매장 하나의 항목 하나를 뜻합니다. 빗금이 촘촘할수록 확인한 문서에서 부정으로 분류된 비율이 높습니다.

칸 안에는 비율뿐 아니라, 실제 문서 수와 긍정 건수도 함께 보여줍니다.

분모에는 긍정과 부정뿐 아니라 혼합과 중립도 포함합니다. 자료가 없는 칸은 근거 없음으로 표시합니다.

숫자로 비교하기를 펼치면 같은 내용을 표로 읽을 수 있습니다.

다만 기간 안의 고객 경험이 매장별 다섯 건보다 적거나 출처 구성이 다르면 비교를 제한합니다.

이 기준은 통계적으로 충분하다는 보장이 아닙니다. 이 화면으로 매장 순위를 매기기보다, 더 확인할 항목을 찾습니다.

## 00:02:35–00:03:20 · 숫자에서 원문 근거로

화면: 행렬 사각형 클릭, 근거 필터, 인용·원문 링크·문서 성격·게시일

사각형을 누르면 해당 매장과 항목의 근거로 이동합니다. 결과 숫자가 어떤 문장에서 나왔는지 확인하는 단계입니다.

근거 카드에는 감정 분류와 항목, 매장명, 인용문이 나옵니다. 아래에서 출처 링크와 게시일도 함께 볼 수 있습니다.

에이아이의 감정 분류가 항상 맞는 것은 아닙니다. 원문을 읽고, 내가 보기에도 그 해석이 맞는지 판단할 수 있어야 합니다.

필터에서는 매장과 항목, 감정, 게시일, 문서 성격을 바꿀 수 있습니다.

고객 경험과 운영자의 설명, 기사, 성격을 확인하지 못한 글을 나눠 봅니다.

날짜 미확인 근거도 따로 살펴볼 수 있지만, 기간 안의 후기 비율과 섞지는 않습니다.

원문 조각의 개수와 문서의 개수도 다릅니다. 한 문서에서 여러 항목의 문장이 나올 수 있기 때문입니다.

## 00:03:20–00:03:55 · 알 수 없는 성별과 연령

화면: 성별·연령별로도 다를까 전체, 미확인 칸, 숫자 표

성별과 연령별로도 경험이 다른지 궁금할 수 있습니다. 하지만 공개 리뷰만으로 작성자의 성별과 나이를 확인할 수는 없습니다.

그래서 이 화면은 확인하지 못한 값을 그대로 미확인으로 남깁니다.

이름이나 프로필 사진, 말투를 보고 성별과 나이를 추측하지 않습니다.

대시 표시는 해당 고객이 영 명이라는 뜻이 아닙니다. 값을 알 수 없다는 뜻입니다.

숫자 표에서도 같은 기준을 적용합니다. 자료가 없는 상태에서 집단별 긍정이나 부정 비율을 만들어내지 않습니다.

확인한 결과와 확인할 수 없는 결과를 구분해야, 이 자료로 내릴 수 있는 판단도 분명해집니다.

## 00:03:55–00:04:28 · 상권 통계는 지역의 배경

화면: 상권의 배경, 공식 조회 링크, 지역 인구 표와 해석 범위

상권 자료는 매장이 있는 지역을 이해하는 배경으로 봅니다. 지역 인구를 이 매장의 고객 수로 바꾸지는 않습니다.

공식 공개 문서에서 지역과 기간, 단위와 숫자가 함께 확인될 때만 값을 표시합니다.

성별과 연령이 만나는 칸도 실제 교차값이 원문에 있어야 채웁니다.

여성 인구와 이십 대 인구를 각각 찾았다고, 두 값을 조합해 이십 대 여성 수를 만들 수는 없습니다.

조건에 맞는 자료가 없으면 미확인으로 남기고, 공식 자료를 더 찾아볼 수 있는 링크를 제공합니다.

이렇게 고객 후기와 지역 통계가 가리키는 대상을 분리해서 읽습니다.

## 00:04:28–00:05:00 · 근거를 읽고 다음 행동 선택

화면: 먼저 바꿀 일, 근거 확인 버튼, 수집 범위와 분석 기준

마지막으로 먼저 바꿀 일을 살펴봅니다. 제안은 우리 매장에서 확인한 근거에 연결됩니다.

근거 확인 버튼으로 돌아가, 어떤 경험 때문에 나온 제안인지 직접 읽을 수 있습니다.

한 문서의 불만을 반복되는 불편으로 확대하지 않습니다. 근거가 부족하면 개선안을 만들기보다 확인을 먼저 안내합니다.

수집 범위와 분석 기준에서는 출처, 제외된 자료, 실제 검색과 에이피아이 호출 기록을 확인할 수 있습니다.

이 앱의 역할은 결론을 대신 정하는 것이 아닙니다. 사장님이 근거를 읽고, 유지할 강점과 먼저 확인할 불편을 고르도록 돕습니다.

## 제작 기준

- 상단: 실제 앱 시연 · 공개 검색 자료. 실행 장면: API 대기 구간 편집.

- 모델과 추론 설정은 상위 세션을 상속했으나 정확한 런타임 값은 확인되지 않음.
