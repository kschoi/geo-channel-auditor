# 5분 시연 대본 — Geo Channel Auditor v0.2.0

5분을 목표로 한 구성입니다. API 대기에 따라 실제 길이는 달라질 수 있습니다.

> 라이너 .EXE-THON 제출용 · 팀 클로클립 · 최경선
> 저장소: https://github.com/kschoi/geo-channel-auditor

`⟨ ⟩`는 촬영 때 나온 값으로 채웁니다. 숫자·표기 차이·메뉴를 미리 정하지 않습니다.

## 촬영 전 준비

```bash
git clone https://github.com/kschoi/geo-channel-auditor.git
cd geo-channel-auditor
uv sync --extra dev
cp .env.example .env
# .env에 LINER_API_KEY 설정. 키 입력 화면은 녹화하지 않습니다.
uv run pytest
uv run ruff check .
uv run uvicorn app.main:app --reload
```

- `http://127.0.0.1:8000`에서 실제 매장명·지역으로 실행합니다. `LIVE` 배지는 키 설정 표시이므로 API 성공 여부도 확인합니다.
- 실제 값·인용문·날짜·출처를 읽고 아래 대본의 빈칸을 채웁니다.
- 대기를 줄여 편집하면 화면에 `대기 구간 편집`을 표시합니다. 실행 시간을 임의로 연출하지 않습니다.
- 데스크톱과 390px 모바일, 저장한 PNG를 확인합니다. 알림·키·비공개 자료는 녹화 범위에서 제외합니다.

## 6장면 진행

| 목표 구간 | 화면 조작 | 내레이션 |
| --- | --- | --- |
| **0:00–0:25 · 문제** | 첫 화면과 통합 검색창 | 같은 매장을 찾아도 사이트마다 영업시간이나 가격이 다를 때가 있습니다. 어느 문장을 보고 무엇을 다시 확인해야 할까요? Geo Channel Auditor는 흩어진 매장 정보를 근거 문장과 함께 정리합니다. |
| **0:25–1:40 · 실제 검색** | `⟨지역·매장명·업종⟩` 입력 후 검색. 대기 중 수집 방식 설명 | 오늘은 ⟨매장명·지역⟩을 검색합니다. Liner Search와 Search Agent가 제공한 제목·요약·발췌를 모읍니다. Router가 값과 인용문을 추출하면 서버가 인용문과 값이 제공된 문자열 안에 있는지 대조합니다. |
| **1:40–2:45 · 근거와 확인할 일** | `항목별 확인 내용`에서 실제 근거 1~2개를 펼침. 날짜 비교 후 `먼저 확인할 일`의 근거로 이동 | 주소·시간·가격·주차·예약·메뉴 언급, 여섯 항목입니다. ⟨값⟩ 옆에 ⟨짧은 인용문⟩과 ⟨게시일·자료 종류⟩가 붙어 있습니다. ⟨실제 비교 결과 또는 날짜 상태⟩를 보고, 먼저 ⟨실제 확인할 일⟩을 확인하면 됩니다. |
| **2:45–3:40 · 카드 생성** | `카드뉴스 만들기` 클릭. 생성 대기 중 사용 범위 설명 | 카드에는 매장·지역과 자료의 메뉴 언급만 정리해 넣습니다. 분석이 원문 전체·운영 주체·현재 사실을 검증한 것은 아닙니다. 자료에서 못 찾았다고 서비스가 없다는 뜻도 아닙니다. 메뉴 판매와 최종 문구는 매장에서 확인해야 합니다. Liner가 문구를 쓰고 브라우저가 디자인 틀에 배치합니다. AI 사진 생성은 아닙니다. |
| **3:40–4:40 · 편집과 PNG 저장** | 제목·본문·캡션 수정 → `카드 색상` 선택 → 장별 PNG 저장 → 파일 열기 | ⟨확인한 문구⟩로 고치고 제목을 짧게 줄이겠습니다. 색상을 고른 뒤 1080×1350 PNG로 저장합니다. 파일을 열면 수정한 문구가 반영된 카드가 보입니다. 캡션은 따로 복사해 사용합니다. |
| **4:40–5:00 · 가치** | 저장한 카드와 검토 화면, 저장소 표시 | 검색한 정보의 근거를 읽고, 확인할 일을 고른 뒤, 직접 고친 카드까지 만듭니다. 매장 정보를 다시 찾고 홍보 문구로 옮기는 수고를 줄이는 도구입니다. 실행 방법과 검증 코드는 저장소에 담았습니다. |

### 3번 장면은 실제 결과에 맞춰 말하기

- `표기가 다름`이 있으면 같은 시간 조건 또는 같은 메뉴 가격의 값·날짜를 나란히 보여줍니다. “표기가 달라 적용 조건을 확인할 후보입니다”라고 설명합니다. 어느 쪽이 사실인지 확정하지 않습니다.
- 날짜 미상·과거 기록·추측 표시가 있으면 실제 표시 하나를 읽습니다. 없으면 이 설명은 생략합니다.
- 확인할 일이 없으면 “추가 확인 항목은 없습니다. 근거와 날짜를 살펴보겠습니다”라고 말합니다. 근거가 없는 항목은 “이번 자료에서 못 찾았습니다”라고 설명합니다.
- 실제 차이가 없으면 비교 장면을 생략합니다. 사례를 꾸미거나 다른 지점 자료를 끼워 넣지 않습니다.

## 촬영자 참고 — 화면 밖에서 확인

아래 내용은 대본을 그대로 읽는 부분이 아니라, 결과를 해석하고 제출 영상을 점검하는 기준입니다.

| 확인 대상 | 기준 |
| --- | --- |
| 날짜와 표기 비교 | 날짜는 API 제공값입니다. 날짜 미상·1년 넘은 자료·추측을 구분합니다. 시간은 항목과 요일 범위, 가격은 같은 메뉴명끼리 비교합니다. 옵션·시점까지 완전히 해석하지 못하므로 최근 자료를 정답으로 단정하지 않습니다. |
| 출처와 운영자 | `자세히 보기`에서 자료 구성·출처·API 로그를 확인합니다. 비중은 이번 URL의 도메인 종류이며 운영 주체는 모두 미확인입니다. 채널 추천 순위나 다른 AI의 인용·검색량을 측정한 값이 아닙니다. |
| 카드 입력과 출처 | 검색 요약 전체나 기존 생성 원고를 다시 사용하지 않습니다. 날짜 미상·과거 자료의 메뉴명은 남을 수 있습니다. 메뉴 언급을 대표메뉴·인기로 설명하지 않습니다. `참고 출처` 링크와 캡션은 PNG에 포함되지 않습니다. |
| 편집과 저장 | 제목 40자·본문 180자·캡션 1500자 이내입니다. 블루·민트·차콜 중 색상을 고릅니다. `1장 PNG 저장`~`3장 PNG 저장`으로 저장하고 한글·줄바꿈·수정 문구·크기를 확인합니다. |
| 키와 호출 | 일회성 키로 분석했다면 카드 생성 전에 다시 입력합니다. 카드 생성은 Router 추가 호출이며 편집·PNG 저장은 API를 호출하지 않습니다. |

## 오류가 나면

- 매장명이 빠졌거나 다른 지점 자료라면 이름·지점·지역을 보완합니다.
- 키 오류·API 실패·시간 초과는 실제 오류 안내를 보여주고 원인을 해결한 뒤 재시도합니다. 가상 결과로 성공을 연출하지 않습니다.
- 자료 문자열과 맞지 않는 추출값은 제외됩니다. 다른 근거가 없다면 못 찾은 상태로 설명합니다.
- 카드 생성·저장 오류는 파일까지 확인한 뒤 재촬영합니다.

## 제출 전 확인

- [ ] 실제 매장과 출처가 맞고, 대본의 빈칸을 실제 결과로 채웠습니다.
- [ ] 값·인용문·날짜·자료 종류와 확인할 일을 화면에서 보여줬습니다.
- [ ] 카드 생성 장면에서 분석 범위와 발행 전 확인 사항을 설명했습니다.
- [ ] 문구 수정·색상 선택·PNG 저장을 실제로 보여줬습니다.
- [ ] 종합 점수·고정 결핍 3건·채널 순위·자동 발행을 현재 기능으로 설명하지 않았습니다.
- [ ] 키·비공개 자료가 보이지 않으며 대기 편집 여부를 표시했습니다.
- [ ] 최종 영상 길이·형식은 제출 요건에 맞췄습니다.

설명란 예시:

> 실제 매장 검색 자료를 값·근거 문장·날짜로 정리하고, 사람이 확인할 일과 편집할 카드뉴스로 연결합니다. 제공된 문자열을 대조하는 도구이며 현재 매장 사실을 인증하지 않습니다. Liner 문구와 브라우저 디자인 틀로 PNG를 만들고, 최종 문구는 발행 전에 확인합니다.
