# 5분 시연 대본 — Geo Channel Auditor v0.2.0

> 라이너 .EXE-THON 제출용 · 팀 클로클립(최경선) · 편집 목표 4분 50초
> 저장소: https://github.com/kschoi/geo-channel-auditor

실제 매장 검색 → 진단 → 카드뉴스 3장 생성 → 문구 수정 → PNG 다운로드를 한 흐름으로 보여줍니다. `⟨ ⟩`는 실제 촬영 화면에서 읽습니다. API 대기 시간을 줄여 편집하면 화면에 `대기 구간 편집`이라고 표시합니다. 아래 구간은 영상 구성 시간이며 API 응답 시간 보장이 아닙니다.

## 1. 촬영 전 준비

```bash
git clone https://github.com/kschoi/geo-channel-auditor.git
cd geo-channel-auditor
uv sync --extra dev
cp .env.example .env
# .env에 LINER_API_KEY 설정. 키 입력 화면은 녹화하지 않습니다.
uv run pytest
uv run ruff check .
uv run uvicorn app.main:app --reload
```

- `http://127.0.0.1:8000`에서 실제 매장 진단과 카드뉴스 생성을 먼저 실행합니다. `LIVE` 배지만 보고 API 성공으로 판단하지 않습니다.
- 예시 3곳은 성수 로우키·서울대입구 우태하피부과·홍대 테이스티버거입니다. 직접 입력도 지역·업종·실제 매장명으로 실행합니다.
- 검색 출처가 실제 매장·지점에 맞는지 확인합니다. 생성 문구의 사실도 출처와 대조합니다.
- 일회성 키로 진단했다면 카드 생성 전 API 설정에 다시 입력합니다. 서버 `.env` 키를 쓰면 다시 입력할 필요가 없습니다.
- 진단에 더해 카드뉴스 생성은 Router 1회가 추가됩니다. 문구 편집·PNG 저장은 추가 API 호출이 없습니다.
- 키 없음·API 실패·검색 근거 부족이면 원인을 해결합니다. 가상 결과로 촬영을 대신하지 않습니다.
- 데스크톱 1600×1000과 모바일 390px에서 생성·편집 화면을 확인합니다. 알림·키 편집 화면·비공개 자료는 녹화 범위에서 제외합니다.
- PNG 3장을 실제로 저장하고 열어 1080×1350 크기, 한글, 줄바꿈, 수정한 문구가 반영되는지 확인합니다.

## 2. 검색과 진단 — 0:00~1:55

| 구간 | 화면 | 내레이션 |
| --- | --- | --- |
| 0:00–0:20 | 첫 화면 검색창 | 매장을 홍보하려고 해도 어떤 정보를 넣어야 할지, 그걸 어떻게 게시물로 만들지 막힙니다. 이 도구는 실제 매장을 검색한 근거로 진단하고, 바로 고쳐 쓸 카드뉴스까지 만듭니다. |
| 0:20–0:45 | `성수 로우키` 예시 또는 실제 매장 직접 입력 | 지역과 매장명, 업종을 넣습니다. 오늘은 ⟨실제 매장명⟩을 검색하겠습니다. 저장된 가상 매장 정보가 아니라 Liner API로 공개 자료를 찾습니다. |
| 0:45–1:10 | Search·Search Agent 진행 | Search가 매장과 상권 자료를 찾고, Search Agent가 고객이 방문 전에 확인할 정보를 정리합니다. 다른 매장 자료가 섞이지 않도록 상호와 지역을 대조합니다. |
| 1:10–1:25 | Router 진행과 결과 | Router가 그 자료를 채널 진단과 원고 초안으로 바꿉니다. 검색이나 생성이 실패하면 가상 결과로 대체하지 않고 오류를 알려줍니다. |
| 1:25–1:55 | 검색 근거·빠진 정보·추천 채널 | ⟨출처 제목⟩에서 이 매장의 자료를 찾았습니다. 먼저 보완할 정보는 ⟨실제 제안⟩이고, 추천 채널은 ⟨채널⟩입니다. 이제 이 근거를 카드뉴스로 만들어 보겠습니다. |

## 3. 카드뉴스 제작·수정·다운로드 — 1:55~3:55

| 구간 | 화면 | 내레이션 |
| --- | --- | --- |
| 1:55–2:15 | `카드뉴스 만들기` 클릭·로딩 | 버튼을 누르면 Liner Router가 검색 근거로 세 장의 문구와 게시물 캡션을 씁니다. 사진 생성이 아니라, 사실을 확인할 수 있는 짧은 카드뉴스 문구를 만드는 단계입니다. |
| 2:15–2:45 | 생성된 3장 차례로 확인 | 첫 장은 ⟨표지 제목⟩, 두 번째는 ⟨확인된 내용⟩, 세 번째는 ⟨안내 문구⟩입니다. 각 장의 참고 출처를 펼쳐 링크도 확인합니다. 근거가 없는 가격이나 운영시간은 임의로 채우면 안 됩니다. |
| 2:45–3:10 | 제목·본문 편집. 미리보기 비교 | 여기서 제목을 더 짧게 바꿔 보겠습니다. ⟨기존 문구⟩를 ⟨수정 문구⟩로 고치면 미리보기에 반영됩니다. 새 사실을 넣을 때는 원래 출처와 한 번 더 대조합니다. |
| 3:10–3:30 | 배경 선택·세 장 확인 | 카드 색상에서 블루, 민트, 차콜 중 하나를 고릅니다. 글자는 이미지 모델이 그리는 대신 브라우저가 배치합니다. 원고를 고친 상태 그대로 PNG에 담습니다. |
| 3:30–3:55 | PNG 개별 저장·다운로드 파일 열기 | 1장 PNG 저장부터 3장 PNG 저장까지 눌러 각각 내려받습니다. 크기는 1080에 1350입니다. 저장한 파일을 열어 수정한 문구와 줄바꿈을 확인했습니다. 이제 매장 사실을 최종 확인한 뒤 게시물로 사용할 수 있습니다. |

## 4. 근거와 차별점 — 3:55~4:50

| 구간 | 화면 | 내레이션 |
| --- | --- | --- |
| 3:55–4:15 | 출처·API 로그 | 실제 매장 검색 근거부터 진단, 카드뉴스 문구까지 이어진다는 점이 핵심입니다. 어떤 출처와 API를 썼는지 확인할 수 있고, 카드뉴스 생성은 Router 한 번을 더 호출합니다. |
| 4:15–4:35 | `Liner 출처 비중`·모바일 편집 화면 | 출처 비중은 Liner 검색 결과와 Search Agent 인용 URL을 중복 제거한 값입니다. 다른 AI의 인용이나 검색량을 측정하는 기능은 아닙니다. 모바일에서도 문구를 읽고 고칠 수 있습니다. |
| 4:35–4:50 | PNG 3장·저장소 | 실제 자료를 찾고, 필요한 정보를 정한 뒤, 편집할 수 있는 홍보물까지 이어집니다. 실행 방법과 테스트는 공개 저장소에 담았습니다. |

## 5. 실패·수정 원칙

| 상황 | 조치 |
| --- | --- |
| 매장명 없는 업종 검색 | 실제 매장명·지역을 넣고 다시 실행합니다. |
| 키 오류·API 실패·시간 초과 | 오류 원인을 해결하고 다시 시도합니다. 실패를 성공으로 편집하지 않습니다. |
| 매장 근거 없음·다른 지점 자료 | 지역·지점명을 좁혀 다시 검색합니다. 일치하지 않는 자료를 매장 사실로 설명하지 않습니다. |
| 카드뉴스 문구 누락·출처 오류 | 생성 오류 안내를 보여주고 다시 시도합니다. 고정 원고로 성공한 척하지 않습니다. |
| 문구가 길거나 확인 필요 표시가 있음 | 출처와 사실을 확인하고 제목·본문을 짧게 고칩니다. |
| PNG 저장 실패·한글·줄바꿈 문제 | 다운로드 파일을 직접 열어 확인한 뒤 수정·재촬영합니다. |

## 6. 제출 전 확인

- [ ] 실제 매장 예시·직접 검색을 실행했고 출처가 해당 매장에 맞습니다.
- [ ] 카드뉴스 3장 생성, 문구 수정, 배경 선택, PNG 3개 다운로드를 실제로 보여줬습니다.
- [ ] 저장한 PNG의 문구·한글·줄바꿈·1080×1350 크기를 확인했습니다.
- [ ] 카드뉴스는 Router 문구+브라우저 Canvas로 만들며 사진·영상 생성이나 자동 발행으로 설명하지 않았습니다.
- [ ] 원고와 카드뉴스에 근거 없는 매장 사실을 넣지 않았습니다.
- [ ] 키·비공개 고객 정보·알림이 영상에 보이지 않습니다.
- [ ] API 대기 편집 여부를 표시했고 촬영 화면과 내레이션이 일치합니다.
- [ ] 5분 미만, 음성·화면 일치, API 이름 자막 확인을 마쳤습니다.
- [ ] 영상 링크·현재 기획서 PDF·저장소 링크를 제출 양식에 넣었습니다.

설명란 예시:

> 실제 매장과 지역을 Liner API로 검색해 채널을 진단하고 카드뉴스 3장을 만듭니다. 문구는 Liner Router, 편집 화면과 PNG 출력은 브라우저 Canvas를 사용합니다. 사진·영상 생성이나 SNS 자동 발행 기능은 없습니다. 검색·생성 실패를 가상 데이터로 대체하지 않으며, 원고와 카드뉴스는 사실 확인 후 발행할 초안입니다.
