# 고객은 우리 매장을 어떻게 볼까?

Geo Channel Auditor의 공개 자료 기반 고객 인식 분석 · v0.3

## 문제와 목적

매장 사장님은 여러 사이트에 흩어진 후기를 읽어도 무엇이 반복되는지, 경쟁점과 어떤 점이 다른지 파악하기 어렵습니다. 이 제품은 검색으로 확보한 후기와 웹문서를 근거별로 정리해 유지할 강점과 확인할 불편을 고르는 데 도움을 줍니다.

측정 대상은 **확인한 공개 문서에 나타난 경험**입니다. 전체 고객 만족도, 시장 점유율, 다른 AI의 인용률은 측정하지 않습니다. 리뷰 사이트 전체 수집을 보장하지 않습니다.

## 사용자와 주요 흐름

1. 사장님이 지역·실제 매장명을 입력합니다. 경쟁점은 같은 지역·업종의 실제 매장을 최대 2개 직접 지정합니다.
2. 최근 90·180·365일 중 분석 기간을 선택합니다. 같은 검색 예산으로 매장별 자료를 수집합니다.
3. 기간 내 후기 문서의 긍정·부정·혼합·중립 건수와 근거를 읽습니다.
4. 품질·서비스·가격 대비 가치·분위기·접근성·대기·청결을 비교합니다.
5. 근거가 연결된 행동 제안을 고르고, 필요하면 별도 매장 정보 검토·카드뉴스 화면으로 이동합니다.

## 필수 기능과 판단 기준

| 기능 | 현재 규칙 | 사용자가 확인할 수 있는 것 |
| --- | --- | --- |
| 공개 자료 수집 | 매장당 Search 3회와 Search Agent 1회. 상권 자료는 별도 Search 2회 | 실제 출처와 성공·실패한 호출 |
| 매장 일치 | 제목·URL의 상호와 자료의 지역 표현 대조, 다른 지점 제외 | 대상 매장, 수집 자료 수, 제외 자료 |
| 근거 추출 | Router가 인용문·자료 ID·항목·감정·글의 성격 추출 | 원문 조각, 게시일, 링크 |
| 검증 | 인용문이 해당 자료 문자열에 있는지 서버에서 대조 | 유효한 근거와 제외 안내 |
| 글의 성격 | 방문 경험·운영자 주장·기사/설명·미확인 분리 | 고객 경험으로 읽힌 근거만 주 집계 |
| 중복 제거 | 추적 URL·네이버 모바일 URL 정규화, 문서×항목 한 번 집계 | 문장 수가 아닌 문서 수 |
| 감정 | 긍정·부정·혼합·중립. 같은 문서에 상반된 경험이면 혼합 | 항목별 건수와 같은 분모의 비율 |
| 기간 | 게시일이 선택 기간 안인 후기만 주 집계. 날짜 미상은 별도 | 시작일·종료일·날짜 미상 건수 |
| 경쟁점 | 같은 수집 예산, 기간, 지역/업종, 출처 구성 확인 | 표와 항목별 자료 수, 비교 한계 |
| 행동 제안 | 유효한 대상 매장 근거에서만 도출 | 제안 이유와 연결 근거 |

감정·글의 성격은 AI의 문장 해석입니다. 인용 일치 검사는 분류의 정확성이나 작성자의 실제 방문을 인증하지 않습니다. 사람이 인용문을 다시 읽을 수 있도록 근거를 노출합니다.

### 비교가 제한되는 경우

기간 내 고객 경험 문서가 매장별 5건 미만이거나 출처 구성이 다르면 비교를 제한합니다. 5건은 비교를 허용하는 최소 문서 수이며 통계적 유의성 기준이 아닙니다. 항목별 자료가 부족한 경우도 해당 항목의 우열을 판단하지 않습니다. 표에 숫자가 있다는 이유로 어느 매장이 더 우수하다고 결론 내리지 않습니다.

지역과 업종 표기가 다르면 같은 시장의 경쟁점인지 재확인하도록 안내합니다. 거리·매출·방문객 수는 추정하지 않습니다. 경쟁점 자동 추천은 이번 구현 범위가 아닙니다.

## 사각형과 빗금으로 읽는 화면

- **항목×매장 행렬:** 크기가 같은 사각형 안의 빗금 밀도로 부정 문서 비율을 표시합니다. 칸에는 실제 문서 수와 긍정·부정 건수를 함께 적습니다. 혼합·중립도 비율 분모에 포함합니다.
- **숫자 표:** 같은 수치를 표로 제공해 색이나 패턴에 의존하지 않고 읽을 수 있게 합니다.
- **성별×연령 표:** 공개 리뷰에 검증 가능한 성별·연령이 없어 미확인으로 표시합니다. 이름·사진·말투로 추정하지 않습니다. `—`는 미확인, `0`은 실제 0건입니다.
- **지역 인구 표:** 공식 공개 자료에서 동일한 지역·기간·지표의 성별×연령 교차값이 원문에 명시된 경우만 표시합니다. 지역 인구는 매장 고객이나 리뷰 작성자가 아닙니다.

성별 합계와 연령별 합계를 곱해서 교차값을 만들지 않습니다. 공개 자료가 특정 값을 숨긴 경우 0으로 바꾸지 않습니다. 현재 별도 공공데이터 인증키 없이 Liner가 찾은 공식 공개 문서의 명시된 값만 검증합니다. 공공 통계 API의 지역별 전수 연동은 구현하지 않았습니다.

## 상권 자료 검증

공식 도메인의 자료만 수치 후보로 받아들이며 인용문, 지역, 기간, 단위, 정수값의 연결을 검사합니다. 성별·연령 모두 직접 연결된 교차 수치여야 해당 칸에 넣습니다. 다른 지역·기간·지표를 합치지 않습니다. 자료가 없거나 연결을 검증하지 못하면 수치 없이 공식 조회 링크와 이유를 보여줍니다.

참고 자료: [서울 상권 상주인구](https://data.seoul.go.kr/dataList/OA-15584/S/1/datasetView.do), [행안부 성별·연령별 주민등록 인구](https://www.data.go.kr/data/15097972/fileData.do), [주민등록 인구 조회](https://jumin.mois.go.kr/ageStatMonth.do). 서울 길단위 유동인구의 성별·연령별 개별 합계는 교차값으로 사용하지 않습니다.

## 화면과 실패 처리

첫 화면에는 핵심 질문, 통합 검색창, 시작 버튼을 둡니다. 경쟁점·기간과 API 키 설정은 접습니다. 결과는 인식 요약, 항목별 근거, 비교 행렬, 성별·연령, 상권 자료, 행동 제안 순으로 읽을 수 있습니다. 상세 출처와 API 기록은 접습니다.

수집 진행을 실시간으로 안내하고 취소를 지원합니다. 일부 수집 실패는 완료된 자료와 실패 건수를 함께 알립니다. 대상 매장 검색이 모두 실패하면 오류로 끝냅니다. 분석 응답 오류·시간 초과는 결과로 가장하지 않습니다. 데스크톱과 390px 모바일에서 확인합니다.

## 보안·성능·데이터 범위

- 서버 환경변수 또는 일회성 Liner 키 사용. 키는 응답·로그에 반사되지 않도록 제거합니다. 브라우저에 영구 저장하지 않습니다.
- 자료·모델 출력은 신뢰하지 않는 입력으로 취급합니다. 화면에는 텍스트로 표시하고 링크는 HTTP(S)만 허용합니다.
- 사용자 고객 명단·리뷰 CSV 업로드는 제공하지 않습니다. 공개 자료만 사용합니다.
- 매장 최대 3개, 동시 수집 최대 3개, 매장별 중복 제거 자료 최대 24개, 공식 상권 자료 최대 12개입니다. 일부 문자열을 읽으며 원문 전체를 수집하지 않습니다.
- 전체 요청은 최대 360초입니다. 브라우저 연결 종료·취소 시 분석 작업을 정리합니다. 공급자에서 이미 처리한 호출의 비용 취소는 보장하지 않습니다.
- 카드뉴스는 별도 검토 흐름에서 대상 매장만 다시 수집합니다. 경쟁점 자료를 홍보 원고에 넘기지 않습니다. 이미지는 별도 버튼으로 생성합니다.

## 완료 기준

1. 실제 공개 검색 결과로 대상 매장과 경쟁점이 구분된다.
2. 원문에 없는 인용·잘못된 자료 ID·다른 매장 근거가 집계에 들어가지 않는다.
3. 중복·혼합 감정·기간 미상·0과 미확인을 정확히 구분한다.
4. 숫자에서 원문과 날짜로 이동할 수 있다.
5. 성별·연령 추정이나 상권 인구의 고객 수 전환이 없다.
6. API 실패·취소·시간 초과·키 반사 검사가 통과한다.
7. 390px 화면에서 페이지 가로 넘침 없이 사용한다.
8. README, 기획서, 5분 시연이 최종 코드와 일치한다.

유료 고객 확보율·매출 개선 등 사업 성과 목표는 아직 정하지 않았습니다. 현재는 근거 추적 가능성, 표시 정확성, 실제 실행 완료 여부를 검증합니다.
